## 3. Bugs found and fixed

### 3.1 Tray icon never appeared
XApp names a status icon's D-Bus name after the program name. `python3 -m linscreencapture.tray` runs as `tray.py`,
so the name was `org.x.StatusIcon.tray_py`, which Mint's `mintreport-tray` (`/usr/lib/linuxmint/mintreport/tray.py`)
already owns. The icon never registered. Fixed by `GLib.set_prgname("linscreencapture-tray")`. Both machines found
this independently; the other machine's commit landed first, and this machine's duplicate was dropped in the rebase.

### 3.2 No icon in Alt+Tab
The studio window had `WM_CLASS "__main__.py"` and no `_NET_WM_ICON`, so Cinnamon could not match it to the
launcher's `StartupWMClass`. Fixed by setting the prgname to the app id in `__main__.py` and a default window icon.
This was also found on both machines; the other machine's version landed. Verified with `xprop`:
`WM_CLASS "com.mensuramedia.LinScreenCapture"`, icons at 16 / 24 / 32 px and up.

### 3.3 Startup Applications showed a blank icon
`services/autostart.py` still wrote `Icon=linscreencapture3`, the retired theme name that `make launcher` now
deletes. It now writes `Icon=com.mensuramedia.LinScreenCapture`; `test_agent` asserts it. (`1751c5e`)

### 3.4 `make test` switched Run at startup off on the developer's desktop
`install.sh --uninstall` removed `$HOME/.config/autostart/<app id>.desktop` even with `--destdir` (staging), and
`test_install_script_uninstalls` runs exactly that. Because the app treats a missing entry as "off", Run at
startup silently went off after every test run.
- `install.sh` now leaves `$HOME` alone under `--destdir`.
- `PreferencesDialog` defaulted its autostart folder to the real config dir; it now follows `settings.root`.
- Regression tests: one runs the installer with a fake `HOME`, the other checks the dialog's folder.
- Verified with a sentinel entry in the real autostart folder over the whole suite. (`f1ed8fc`)

The bug was found by bisecting the test files with that sentinel; it took five minutes once the sentinel existed.
Worth repeating whenever a test touches desktop integration.

### 3.5 The arrow faded while being drawn
`EditorController._draw_overlay` capped the live preview at 60 % opacity while drawing. The preview now uses the
real colour and opacity. While *drawing*, only the shadow waits for release: measured at 21 ms a frame for a shadowed
1400 × 800 arrow and 16 ms for a 1000-point pen stroke. Moves reuse the cached shadow (§4.2). The regression test
compares the preview's and the committed layer's alpha (255 both; 153 before the fix).

### 3.6 The Callout's Shadow switch did nothing
`callout` was not in `SHADOW_KINDS`. Now it is (with `step` and `image`).

## 4. Features

### 4.1 A Shadow switch on every marking tool
Arrow, Line, Box, Circle, Pen, Marker, Text, Callout, **Step** (new switch) and **Image** (new switch +
Intensity). Fill, Eraser, Blur, Pixelate and the Area tools have none by design: they fill, clear or redact pixels.

### 4.2 Pasted-image shadow, kept through flatten
- A pasted image casts the shadow of its own alpha, so a cut-out PNG casts its shape. The shadow uses sigma 6 and
  offset 4, close to the stage's page shadow.
- It is on by default (`[Tools] shadow_image=true`, `shadow_intensity_image=0.45`).
- The image style never follows the Universal switch.
- The shadow is drawn by `annotations.draw`, so Flatten, Save and Copy bake it into the pixels.
- The blurred silhouette is now cached module-wide by shape relative to the layer's origin. A moved layer, or the
  drag preview's fresh copy, reuses it instead of blurring again on every motion event. Before, a large shadowed
  image would have lagged while dragging.

### 4.3 The page grows to fit a pasted or moved image
- An image layer that is pasted, moved, nudged, resized or duplicated past the page edge grows the page:
  - only on the overflowing sides
  - to the layer's painted extent (shadow included) plus 20 px
  - transparent (white in JPEG)
  - capped at 16384 px a side.
- It is one undo step with the edit (`Compound`, `UndoStack.amend`). Every other layer shifts with the old page, and
  the view scrolls so the picture stays still.
- The page never shrinks by itself; Crop trims it.
- Pastes now land at 1:1 instead of being shrunk to fit; *Fit* shrinks one into the page, shadow included.
- Not built yet: the dashed outline of the future page while dragging (`docs/EDITOR-CANVAS-EXPANSION.md` §4.3).

### 4.6 Rotate pasted images, the Page group, double-click paste, round handles
Branch `feat/stage-rotate-fill`, requested 2026-10-18.

- **Rotate.** A selected pasted image has a round rotate handle on a stem above its top edge; drag to turn it
  about its centre, Shift for 15° steps. The header's `↻ N°` button opens an Angle spin, 90° left / right and an
  upright reset. A turned image keeps working like an upright one: handles on its own frame, resize along its own
  sides with the opposite corner fixed, clicks hit the turned picture, page growth and Fit use its turned extent,
  its shadow follows the turn (drawn on release while dragging the handle). Undo restores the angle, also after a
  page rotation, which now turns pasted images with the page instead of stretching them.
- **Page group** in the right rail: Width and Height set the page size about its centre (one undo step; layers stay
  on the picture). Fill paints a colour behind transparent parts and is saved, copied and flattened with the image
  (undoable; the colour button remembers the last colour). Stage sets the workspace colour around the page, with a
  reset to the theme's; it is a setting and never part of the image.
- **Clipboard tray:** double-click a cell to paste that copy into the stage; one click still opens its preview.
- **Round handles** everywhere a layer is selected.
- **Fixed on the way:** the header strip showed stale values after Ctrl+Z / Ctrl+Y; a selected image forced the
  window to 1450 px (wider than a 1366 px screen). The strip now scrolls inside the header instead.
- Not done: the collapsed right rail has no Page controls; Image → Flip mirrors a pasted image's position but not its
  pixels (as before); each spin step on Width / Height is its own undo step.
- Tests: 173 (+23): `tests/model/test_rotate_and_page.py` (16), 5 shell tests, 2 tray tests.
