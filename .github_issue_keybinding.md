## Bug Report: Keybinding Registration — Cross-DE Reliability Issues

### Summary

LinScreenCapture's automatic keybinding registration ("Set as default screenshot app" in Settings) has been hardened for **Cinnamon (Linux Mint)** but has unresolved issues on other desktop environments that may cause **silent failures, user data loss (GNOME), or no keybinding at all (KDE/Wayland)**.

These issues affect any Debian-based distro running GNOME, XFCE, MATE, KDE, or Wayland sessions.

### Severity by DE

| DE | Distros | Severity | Summary |
|---|---|---|---|
| Cinnamon | Linux Mint | **Working** | Hardened in v1.4.0 (commits `ccd3425`, `ec1e13d`, `5666d09`, `f8d29cd`, `88493c8`) |
| GNOME | Ubuntu, Pop!_OS, Debian | **Critical** | Overwrites ALL user custom keybindings on registration |
| XFCE | Xubuntu, MX Linux | **Medium** | Doesn't disable xfce4-screenshooter default binding |
| MATE | Ubuntu MATE | **Medium** | Doesn't work with Compiz; doesn't disable mate-screenshot |
| KDE | Kubuntu, KDE Neon | **High** | X11 fallback can't override Spectacle; no Wayland support |

### Critical Issue: GNOME Custom Keybindings Overwrite

`gnome_register()` in `src/keybinding_manager.c` line 194 sets:
```
org.gnome.settings-daemon.plugins.media-keys custom-keybindings = ['/…/linscreencapture/']
```

This **replaces** the entire list instead of appending. Any custom keyboard shortcuts the user configured in GNOME Settings are silently removed from the active list.

### Additional Issues

1. **GNOME 42+**: `show-screenshot-ui` keybinding not disabled — GNOME's built-in screenshot tool may intercept PrintScreen
2. **XFCE**: Custom binding added but `xfce4-screenshooter` default not removed — both may fire
3. **MATE**: Registration writes to Marco schema but has no effect if user runs Compiz (MATE Tweak option)
4. **KDE**: Raw `XGrabKey` fallback cannot override `kglobalaccel5`; completely non-functional on Wayland
5. **All DEs**: No error reporting — all shell commands redirect stderr to `/dev/null`, failures are silent
6. **Cinnamon**: Uses hardcoded `custom0` slot — overwrites any existing user `custom0` binding
7. **Wayland**: No support for `org.freedesktop.portal.GlobalShortcuts` or XDG portal screenshot API

### Affected Files

- `src/keybinding_manager.c` — all DE-specific register/unregister functions
- `src/main_window.c` — XGrabKey fallback, X11 event filter, settings UI

### User Impact

- **GNOME users** who enable "Set as default screenshot app" will lose all custom keyboard shortcuts
- **KDE/Wayland users** will see no effect (silent failure)
- **XFCE/MATE users** may experience double-firing or no response depending on DE configuration
- **All users** receive no feedback when registration fails

### Recommended Workaround

Users on non-Cinnamon DEs should **not** use the "Set as default screenshot app" checkbox. Instead, manually configure a keyboard shortcut in their DE's settings pointing to:
```
/usr/bin/linscreencapture --capture
```
(or the path to their LinScreenCapture binary)

### Recommended Fixes (Future)

Each DE path should match the Cinnamon implementation's pattern:
1. **Append** to existing keybinding lists instead of overwriting
2. **Disable** the DE's built-in screenshot tool for the chosen key
3. **Force reload** so changes take effect without logout
4. **Restore defaults** on unregister
5. **Report errors** to the user via the Settings UI status bar
6. **Detect and avoid** custom-slot collisions
7. **Wayland**: Implement `org.freedesktop.portal.GlobalShortcuts` fallback
